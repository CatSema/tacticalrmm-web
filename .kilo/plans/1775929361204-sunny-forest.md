# План: правила перевода и поэтапный план полного i18n

## Цель

Создать 2 рабочих документа для ИИ и команды:

1. файл с жесткими правилами перевода интерфейса на русский;
2. файл с поэтапным планом, который доводит проект до полного перевода.

Оба документа должны быть пригодны для прямого использования ИИ-агентом без дополнительного контекста.

## Что будет создано

### 1) Правила перевода (AI-ready)

- **Путь:** `docs/i18n/translation-rules.ru.md`
- **Назначение:** единый стандарт, который ИИ обязан соблюдать при переводе строк.
- **Структура документа:**
  - Область применения и обязательность правил.
  - Терминология Tactical RMM (глоссарий: Agent, Check, Alert, Script, Policy, Site, Client и т.д.)
  - Тон и стиль (коротко, нейтрально, без англицизмов там, где есть устоявшийся русский эквивалент).
  - Формальные правила для ключей и строк:
    - не менять смысл, порядок переменных, плейсхолдеры и спец-токены;
    - сохранять `%s`, `{name}`, `{{var}}`, HTML-теги, markdown, ссылки, команды;
    - не переводить технические идентификаторы, API-поля, имена продуктов/брендов;
    - единообразие кнопок/статусов/системных сообщений.
  - Правила pluralization и числительных (1/2-4/5+ для русского, где применимо).
  - Правила для ошибок и уведомлений (действие + причина + следующий шаг).
  - Правила пунктуации и регистра для UI-элементов.
  - Список «запрещено» (дословные кальки, сокращения без контекста, изменение логики).
  - Чеклист качества перед коммитом (lint переводов, нет пропущенных ключей, нет EN в RU и наоборот).
  - Минимальный шаблон PR/commit для переводов.

### 2) Поэтапный план полного перевода

- **Путь:** `docs/i18n/full-translation-rollout-plan.ru.md`
- **Назначение:** пошаговый roadmap до состояния «полностью переведено».
- **Структура документа:**
  - Критерии готовности (Definition of Done):
    - все пользовательские строки вынесены в i18n-ключи;
    - русский покрывает 100% используемых ключей;
    - fallback на `en` не срабатывает в штатных сценариях;
    - Quasar UI и кастомный UI синхронно локализуются.
  - Фаза 0: Подготовка инфраструктуры i18n
    - `vue-i18n` boot-файл, подключение `Quasar.lang`, структура `src/i18n/{en,ru}`.
  - Фаза 1: Инвентаризация строк
    - сбор hardcoded строк по `src/views`, `src/layouts`, `src/components`, `src/ee`;
    - классификация по доменам и приоритетам.
  - Фаза 2: Нормализация ключей
    - единый namespace (`common`, `auth`, `agents`, `checks`, `alerts`, `settings`, `reporting`, ...).
  - Фаза 3: Перевод критического пути
    - Login, Dashboard, Navigation, Agent карточка/таблицы, основные диалоги.
  - Фаза 4: Перевод остальных модулей
    - core + EE разделы, модалки, уведомления, пустые состояния, ошибки.
  - Фаза 5: Техническая валидация
    - проверка отсутствующих/лишних ключей;
    - smoke-проход на RU и EN;
    - визуальная проверка переполнений текста.
  - Фаза 6: Релиз и защита от регрессий
    - правило «новая строка только через i18n»;
    - CI-проверка паритета ключей `en/ru`.
  - Таблица артефактов по каждой фазе: вход, действия, результат, критерий завершения.

## Детализированный порядок выполнения

1. Создать каталог `docs/i18n`.
2. Написать `translation-rules.ru.md` в императивном формате для ИИ (обязательно/запрещено/проверить).
3. Добавить в rules-файл мини-глоссарий доменных терминов и примеры правильного/неправильного перевода.
4. Написать `full-translation-rollout-plan.ru.md` с фазами, задачами, контрольными точками и DoD.
5. Включить в план отдельный раздел «Как понять, что проект переведен полностью» (объективные метрики).
6. Провести самопроверку документов:
   - нет двусмысленных формулировок;
   - шаги выполнимы по текущему стеку (Quasar + Vue 3 + vue-i18n);
   - документы не противоречат друг другу.

## Проверка после создания файлов

- Файлы существуют по указанным путям.
- Формулировки пригодны для автоматического исполнения ИИ (четкие MUST/SHOULD/NEVER).
- В roadmap есть конечное состояние «полный перевод завершен» и измеримые критерии.

## Риски и меры

- Риск: разночтения терминов в разных модулях.
  - Мера: единый глоссарий + обязательная ссылка на него в начале rules-файла.
- Риск: пропуски строк в EE/редких модалках.
  - Мера: фаза инвентаризации по директориям + финальный аудит отсутствующих ключей.
- Риск: ухудшение UX из-за длинных RU-строк.
  - Мера: отдельный шаг UI-проверки переполнений и сокращения формулировок.

## Результат внедрения этого плана

После выполнения будет два документа, достаточных для запуска и доведения полного перевода проекта на русский язык с предсказуемым качеством и контролем регрессий.
