# Поэтапный план полного перевода проекта на русский

## Цель

Довести проект до состояния, при котором весь пользовательский интерфейс полностью локализован на русский язык, а новые изменения не ломают локализацию.

## Definition of Done (финальные критерии)

- 100% пользовательских строк вынесены в i18n-ключи.
- 100% используемых ключей имеют значения в `ru`.
- В штатных сценариях отсутствуют срабатывания fallback на `en`.
- Язык Quasar-компонентов и кастомных компонентов переключается синхронно.
- CI проверяет паритет `en/ru` и блокирует регрессии.

## Область работ

- Основной UI: `src/views`, `src/layouts`, `src/components`, `src/core`, `src/composables`.
- EE-модули: `src/ee/**`.
- Вспомогательные сообщения/уведомления: `src/utils`, `src/stores`, `src/store`, `src/mixins`.

## Фаза 0. Подготовка инфраструктуры i18n

**Вход:** текущий проект Quasar/Vue без полной i18n-интеграции.

**Действия:**

- Установить и подключить `vue-i18n` (если еще не подключен в рантайме).
- Создать boot-файл `src/boot/i18n.ts`.
- Подключить boot в `quasar.config.js`.
- Создать структуру словарей: `src/i18n/en` и `src/i18n/ru`.
- Добавить синхронное переключение `vue-i18n` + `Quasar.lang` (`en-US`, `ru`).
- Настроить locale source: профиль пользователя/хранилище/браузер + fallback `en`.

**Артефакты:**

- Рабочий i18n boot и базовые словари.
- Базовые ключи `common.*` (кнопки, общие статусы, системные действия).

**Критерий завершения:**

- Переключение языка работает глобально, без перезагрузки приложения.

## Фаза 1. Инвентаризация строк

**Вход:** рабочая инфраструктура i18n.

**Действия:**

- Собрать hardcoded-строки по директориям:
  - `src/views/**`
  - `src/layouts/**`
  - `src/components/**`
  - `src/core/**`
  - `src/ee/**`
- Разделить строки на категории:
  - критический путь (логин, дашборд, навигация, подтверждения);
  - операционные модули (agents/checks/alerts/scripts/tasks);
  - редкие/админские экраны (settings/reporting/integrations/EE).
- Выделить строки, требующие pluralization и интерполяции.

**Артефакты:**

- Реестр строк с указанием файла, модуля, приоритета и типа (label/message/error/dialog).

**Критерий завершения:**

- Есть полный список строк для миграции и порядок исполнения.

## Фаза 2. Нормализация ключей и словарей

**Вход:** реестр строк.

**Действия:**

- Утвердить namespaces:
  - `common`, `auth`, `dashboard`, `navigation`, `agents`, `checks`, `alerts`, `scripts`, `tasks`, `software`, `settings`, `reporting`, `errors`, `notifications`.
- Принять формат именования: `domain.section.action`.
- Разнести ключи по модульным JSON-файлам, а не в один большой файл.
- Завести и закрепить глоссарий терминов из `translation-rules.ru.md`.

**Артефакты:**

- Единая схема ключей и структура словарей для `en` и `ru`.

**Критерий завершения:**

- Новые строки добавляются только по утвержденной схеме ключей.

## Фаза 3. Перевод критического пути

**Вход:** нормализованные ключи и словари.

**Действия:**

- Перевести и подключить i18n на экранах:
  - Login / SessionExpired / InitialSetup / TOTP;
  - MainLayout (навигация, меню, профиль, выход);
  - Dashboard (ключевые карточки/таблицы/фильтры);
  - базовые `ConfirmDialog`/`Notify`/общие модалки.
- Убрать hardcoded-строки из этих экранов.

**Артефакты:**

- Полностью локализованный критический пользовательский путь.

**Критерий завершения:**

- Пользователь может войти и выполнить базовые действия полностью на русском.

## Фаза 4. Перевод всех функциональных модулей

**Вход:** критический путь покрыт.

**Действия:**

- Последовательно перевести домены:
  1. `agents`
  2. `checks`
  3. `alerts`
  4. `scripts`
  5. `tasks`
  6. `software`
  7. `settings`
  8. `reporting` и `src/ee/**`
- Для каждого домена:
  - вынести строки в ключи;
  - заполнить `en` и `ru`;
  - проверить плейсхолдеры/pluralization;
  - пройти smoke-сценарий по экрану.

**Артефакты:**

- Полные `en/ru` словари по всем доменам.

**Критерий завершения:**

- Нет непереведенных пользовательских строк в функциональных модулях.

## Фаза 5. Техническая и UX-валидация

**Вход:** все домены переведены.

**Действия:**

- Проверить отсутствие missing keys и лишних ключей.
- Проверить соответствие плейсхолдеров между `en` и `ru`.
- Выполнить smoke на `ru` и `en`.
- Проверить UI на переполнение строк: кнопки, таблицы, диалоги, тултипы.
- Прогнать линт и сборку.

**Артефакты:**

- Отчет валидации с исправленными дефектами.

**Критерий завершения:**

- Нулевой блокирующий дефект по локализации перед релизом.

## Фаза 6. Релиз и защита от регрессий

**Вход:** валидация завершена.

**Действия:**

- Зафиксировать правило: новая UI-строка добавляется только через i18n.
- Добавить CI-проверку паритета ключей `en/ru`.
- Добавить CI-проверку несоответствия плейсхолдеров.
- Документировать процесс добавления новых переводов для разработчиков.

**Артефакты:**

- Обновленные процессы разработки и автоматические проверки.

**Критерий завершения:**

- Любая регрессия i18n обнаруживается автоматически до merge.

## Как понять, что проект переведен полностью

Проект считается полностью переведенным, когда одновременно выполнены метрики:

1. Покрытие ключей: `used_keys == ru_keys == en_keys`.
2. Missing key warnings в runtime: `0` в smoke/E2E.
3. Hardcoded UI-строк в целевых директориях: `0` (кроме брендов, кода, протоколов и API-идентификаторов).
4. Критические пользовательские сценарии проходят на `ru` без fallback на `en`.
5. Визуальные дефекты локализации (обрезка/переполнение): `0` блокирующих.

## Порядок исполнения по итерациям

- Итерировать доменами, один домен за PR.
- В каждом PR:
  - миграция строк в ключи;
  - обновление `en/ru`;
  - проверка качества;
  - короткий отчет по покрытию.

Это обеспечивает безопасный инкрементальный выход на полный перевод без массовых труднообозримых изменений.
