# Правила перевода интерфейса на русский (для ИИ)

## 1) Назначение

Этот документ задает обязательные правила локализации UI проекта Tactical RMM на русский язык.

Правила предназначены для ИИ-агентов и людей. При конфликте с личными предпочтениями переводчика всегда применять этот документ.

## 2) Обязательность

- `MUST`: требование обязательно к исполнению.
- `SHOULD`: рекомендуется, отклонение допускается только при обосновании в PR.
- `NEVER`: запрещено.

## 3) Общие принципы

- `MUST` переводить смысл, а не дословную форму.
- `MUST` сохранять функциональную точность: перевод не должен менять действие, статус, степень критичности ошибки.
- `MUST` делать строки короткими и понятными для админского интерфейса.
- `SHOULD` придерживаться нейтрального делового тона без разговорных форм.
- `NEVER` добавлять от себя новую информацию, которой нет в исходной строке.

## 4) Глоссарий и терминология

Использовать единообразные термины во всех модулях.

| Английский термин | Канонический перевод | Примечание                                     |
| ----------------- | -------------------- | ---------------------------------------------- |
| Agent             | Агент                | Сущность в системе, не переводить как "клиент" |
| Client            | Клиент               | Организация/заказчик                           |
| Site              | Сайт                 | Локация клиента                                |
| Check             | Проверка             | Мониторинговая проверка                        |
| Alert             | Оповещение           | Не смешивать с "тревогой"                      |
| Policy            | Политика             | Набор правил                                   |
| Task              | Задача               | Плановое или ручное действие                   |
| Script            | Скрипт               | Не переводить как "сценарий" в UI              |
| Dashboard         | Панель мониторинга   | Допустимо: "Панель" при дефиците места         |
| Service           | Служба               | Windows service                                |
| Event Log         | Журнал событий       |                                                |
| Run               | Запустить            | Для кнопок действий                            |
| Retry             | Повторить            |                                                |
| Success           | Успешно              | Статус выполнения                              |
| Failed            | Ошибка               | Для статуса/уведомления                        |
| Pending           | В ожидании           |                                                |

### Что не переводить

- `NEVER` переводить: `Tactical RMM`, названия продуктов, бренды, URL, API endpoint, имена переменных, ключи JSON, команды терминала.
- `NEVER` переводить технические идентификаторы: `agent_id`, `site_id`, `SMTP`, `SSH`, `RDP`, `URL`, `DNS`.

## 5) Правила для i18n-ключей

- `MUST` использовать key-based подход: UI использует ключи, а не встроенные русские строки.
- `MUST` придерживаться namespace-структуры: `common.*`, `auth.*`, `agents.*`, `checks.*`, `alerts.*`, `settings.*`, `reporting.*`.
- `MUST` давать ключам стабильные имена по смыслу, а не по тексту.
- `NEVER` использовать английский текст как ключ.

Пример:

- хорошо: `agents.actions.runScript`
- плохо: `"Run Script"`

## 6) Плейсхолдеры, переменные, разметка

- `MUST` сохранять все плейсхолдеры без изменений: `%s`, `%d`, `{name}`, `{count}`, `{{ value }}`.
- `MUST` сохранять порядок и количество переменных, если код ожидает фиксированную сигнатуру.
- `MUST` сохранять HTML/Markdown-структуру и спец-токены.
- `NEVER` переводить содержимое inline-кода, команд и путей.

Пример:

- Source: `Delete agent {agent} permanently?`
- RU: `Удалить агента {agent} безвозвратно?`

## 7) Множественное число и числительные

- `MUST` использовать механизмы pluralization `vue-i18n` для строк с количеством.
- `MUST` учитывать русские формы: `1`, `2-4`, `5+`, а также `0`.
- `NEVER` строить формы вручную в коде через конкатенацию строк.

Пример шаблона:

```json
{
  "agents": {
    "selected": "Нет выбранных агентов | Выбран {count} агент | Выбрано {count} агента | Выбрано {count} агентов"
  }
}
```

## 8) Кнопки, статусы, уведомления

- `MUST` использовать короткие глаголы в кнопках: `Сохранить`, `Отмена`, `Удалить`, `Запустить`.
- `MUST` переводить статусы единообразно в таблицах, карточках и фильтрах.
- `SHOULD` формировать уведомления по шаблону: действие -> результат -> причина (если есть).

Пример уведомления:

- хорошо: `Не удалось сохранить настройки: неверный SMTP-хост.`
- плохо: `Ошибка! Что-то пошло не так.`

## 9) Стиль, пунктуация, регистр

- `MUST` использовать обычную русскую орфографию и пунктуацию.
- `MUST` не злоупотреблять восклицательными знаками и КАПСОМ.
- `SHOULD` избегать канцелярита и длинных оборотов.
- `SHOULD` сохранять единый стиль заголовков внутри модуля.

## 10) Запрещено

- `NEVER` делать дословные кальки, ухудшающие смысл.
- `NEVER` менять логику через перевод (например, `Disable` -> `Включить`).
- `NEVER` терять отрицание (`not`, `failed`, `denied`).
- `NEVER` объединять или дробить строки, если это ломает интерполяцию.

## 11) Контроль качества перед merge

- `MUST` обеспечить паритет ключей `en` и `ru`.
- `MUST` убедиться, что для используемых ключей нет fallback на `en` в штатном UI-потоке.
- `MUST` проверить критические экраны: логин, дашборд, карточка агента, модальные подтверждения.
- `MUST` проверить переполнение текста (кнопки, таблицы, диалоги, тултипы).
- `SHOULD` запускать линт и сборку проекта.

Мини-чеклист:

1. Нет отсутствующих ключей в `ru`.
2. Нет лишних ключей, удаленных из `en`.
3. Плейсхолдеры и токены совпадают.
4. Термины соответствуют глоссарию.
5. Визуально UI читаем на RU.

## 12) Формат работы ИИ по каждой пачке перевода

- `MUST` сначала вынести строки в ключи, потом заполнить `en` и `ru`.
- `MUST` переводить модульно (один домен за итерацию).
- `MUST` в отчете указывать:
  - список измененных файлов;
  - новые/измененные namespaces;
  - результаты проверки качества;
  - известные ограничения (если есть).

## 13) Шаблон commit/PR для переводов

Заголовок:
`i18n: localize <module> to ru and align key parity`

Описание:

- Added/updated i18n keys for `<module>` in `en` and `ru`.
- Replaced hardcoded UI strings with i18n lookups.
- Verified key parity and placeholder consistency.
